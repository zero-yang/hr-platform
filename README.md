# HR Resume Screening Platform

一个基于 Next.js、Ant Design、Sass、PostCSS、TypeScript、Supabase 和 DeepSeek 的简历筛选 Web 应用。

## 本地运行

```bash
npm install
npm run dev
```

本地环境在 `.env.local` 中配置：

```bash
NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxx
DEEPSEEK_API_KEY=sk-xxx
```

线上环境在部署平台配置同名环境变量。也可以用 `.env.production` 管理线上构建变量、`.env.local` 管理本地变量；不要提交包含真实密钥的环境文件。

打开系统配置页，只需要选择 DeepSeek 模型名称即可使用。

## Supabase 建表 SQL

```sql
create table if not exists job_post (
  id bigint generated by default as identity primary key,
  name text not null,
  requirement text not null,
  scoring_criteria text not null,
  created_at timestamptz default now()
);

create table if not exists talent_pool (
  id bigint generated by default as identity primary key,
  name text not null,
  phone text not null,
  email text not null,
  education text not null,
  school text not null,
  work_years text not null,
  target_position text not null,
  resume_content text not null,
  resume_score text not null,
  evaluation text not null,
  created_at timestamptz default now()
);
```

如果使用前端 publishable/anon key 写入数据，需要在 Supabase 中配置合适的 RLS 策略。

## Supabase RLS 策略

前端请求使用 `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`，对应 Supabase 的 `anon` 角色。SQL Editor 默认使用 `postgres` 角色，能看到数据不代表前端 `anon` 角色也能读取。若前端 Network 中 `job_post` 返回 `[]`，但 SQL Editor 能查询到数据，通常是 RLS 没有放行 `anon` 读取。

在 Supabase SQL Editor 中执行 [supabase/rls-policies.sql](/supabase/rls-policies.sql) 可放行当前应用需要的最小访问：

- `job_post`: 允许 `anon` 读取岗位要求和评分标准
- `talent_pool`: 允许 `anon` 写入和读取人才评估记录
